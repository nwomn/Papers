# 高性能算子设计经验：从 mHC I/O 分析中学习

## 1. 核心教训

mHC 论文的 I/O 分析揭示了一个关键事实：

> **大多数 GPU 操作是内存受限的，而非计算受限的。**

因此，设计高性能算子的首要目标是**最小化内存访问**，而非最小化计算量。

---

## 2. I/O 分析方法论

### 2.1 分析步骤

```
1. 分解操作为原子步骤
2. 统计每步的读/写元素数
3. 计算总 I/O 量
4. 评估算术强度 (AI)
5. 判断瓶颈类型
6. 针对性优化
```

### 2.2 算术强度计算

$$\text{Arithmetic Intensity (AI)} = \frac{\text{FLOPs}}{\text{Bytes Accessed}}$$

| AI 值 | 瓶颈类型 | 优化方向 |
|-------|----------|----------|
| < 10 | **内存受限** | 减少 I/O、Kernel Fusion |
| 10-100 | 混合 | 两者都优化 |
| > 100 | **计算受限** | 使用 Tensor Core |

**H100 的临界点**：约 300 FLOPs/Byte（990 TFLOPS / 3.35 TB/s）

## 3. 经验 1：Kernel Fusion

### 3.1 问题

每个独立 kernel 都需要：
- 从 Global Memory 读取输入
- 将结果写回 Global Memory
- Kernel launch 开销

### 3.2 解决方案

**将有数据依赖的操作融合到单个 kernel**：

```
优化前（3 个 kernel）：
Kernel 1: y = f(x)     → 读 x, 写 y
Kernel 2: z = g(y)     → 读 y, 写 z
Kernel 3: w = h(z)     → 读 z, 写 w
总 I/O: 读 x+y+z, 写 y+z+w = 6 次传输

优化后（1 个 fused kernel）：
Fused:    w = h(g(f(x)))  → 读 x, 写 w
总 I/O: 读 x, 写 w = 2 次传输
```

### 3.3 mHC 的实践

论文将 $\mathcal{F}_{\text{post,res}}$ 融合为单个 kernel：

| 操作 | 优化前读取 | 优化后读取 |
|------|-----------|-----------|
| $\mathcal{H}^{\text{post}}$ 应用 | $C + n$ | - |
| $\mathcal{H}^{\text{res}}$ 应用 | $nC + n^2$ | - |
| 残差合并 | $2nC$ | - |
| **融合后** | - | $(n+1)C + n^2 + n$ |

**读取减少**：从 $(3n+1)C + n^2 + n$ 降到 $(n+1)C + n^2 + n$

### 3.4 Fusion 决策准则

```python
def should_fuse(op1, op2):
    """判断是否应该融合两个操作"""

    # 1. 数据依赖检查
    if op2.inputs not in op1.outputs:
        return False  # 无依赖，可以并行而非融合

    # 2. 中间结果检查
    if op1.output_used_elsewhere:
        return False  # 中间结果被其他操作使用

    # 3. 资源检查
    if combined_register_usage > MAX_REGISTERS:
        return False  # Register 压力过大

    if combined_shared_memory > MAX_SHARED_MEM:
        return False  # Shared memory 不足

    return True
```

## 4. 经验 2：混合精度策略

### 4.1 核心思想

- **存储/传输**：使用低精度（BF16/FP16）节省带宽
- **计算**：使用高精度（FP32）保证数值稳定

### 4.2 mHC 的混合精度配置

| 数据 | 精度 | 原因 |
|------|------|------|
| $x_l$ 存储 | BF16 | 节省 50% 带宽 |
| 映射矩阵 $\mathcal{H}$ | FP32 | 保证数值精度 |
| 中间计算 | FP32 | 避免精度损失 |
| $x_{l+1}$ 存储 | BF16 | 节省 50% 带宽 |

### 4.3 实现模式

```python
@tl.kernel
def mixed_precision_kernel(
    x: tl.Tensor[..., tl.bfloat16],  # 输入 BF16
    H: tl.Tensor[..., tl.float32],   # 参数 FP32
    y: tl.Tensor[..., tl.bfloat16],  # 输出 BF16
):
    # 读取时转换为 FP32
    x_fp32 = x.to(tl.float32)

    # FP32 计算
    result = compute(x_fp32, H)

    # 写回时转换为 BF16
    y = result.to(tl.bfloat16)
```

## 5. 经验 3：重计算 vs 存储权衡

### 5.1 问题

反向传播需要中间激活，但保存所有激活会导致显存爆炸。

### 5.2 权衡分析

| 策略 | 优点 | 缺点 |
|------|------|------|
| **全存储** | 反向快 | 显存大 |
| **全重计算** | 显存小 | 反向慢（2× 计算） |
| **选择性重计算** | 平衡 | 需要仔细设计 |

### 5.3 mHC 的重计算策略

**保存**：
- 每 $L_r$ 层的第一层输入 $x_{l_0}$
- 每层的层函数输出 $\mathcal{F}(\cdot)$

**丢弃（反向时重计算）**：
- 映射矩阵 $\mathcal{H}^{\text{pre}}, \mathcal{H}^{\text{post}}, \mathcal{H}^{\text{res}}$
- 所有中间结果

### 5.4 最优重计算块大小

$$L_r^* = \sqrt{\frac{nL}{n+2}}$$

**推导**：最小化总显存占用
$$\text{Memory} = \underbrace{nC \times \lceil \frac{L}{L_r} \rceil}_{\text{常驻存储}} + \underbrace{(n+2)C \times L_r}_{\text{临时存储}}$$

对 $L_r$ 求导并令其为 0，得到最优解。

**27B 模型示例**（$n=4$, $L=60$）：
$$L_r^* = \sqrt{\frac{4 \times 60}{6}} \approx 6.3 \approx 6 \text{ 层}$$

## 6. 经验 4：显存占用估算

### 6.1 估算公式

对于 Transformer 训练，显存主要由以下部分组成：

$$\text{Memory} = \text{Parameters} + \text{Gradients} + \text{Optimizer States} + \text{Activations}$$

| 组件 | 大小（FP16/FP32 混合训练） |
|------|---------------------------|
| Parameters | $2 \times N$ bytes |
| Gradients | $2 \times N$ bytes |
| Optimizer (AdamW) | $8 \times N$ bytes（m, v 各 FP32） |
| Activations | 取决于 batch size 和 sequence length |

### 6.2 mHC 的额外显存

| 组件 | 增量 |
|------|------|
| 残差流扩展 | $(n-1) \times C \times B \times T$ per layer |
| 映射矩阵参数 | $(n^2 + 2n) \times L$ per layer |
| 重计算缓存 | $nC \times \lceil \frac{L}{L_r} \rceil \times B \times T$ |

## 7. 经验 5：Pipeline 通信优化

### 7.1 问题

Pipeline 并行中，stage 之间的通信是同步的，会造成 bubble。

### 7.2 解决方案

**通信-计算重叠**：

```
传统方式：
[Compute Stage 1] → [Send] → [Recv] → [Compute Stage 2]
                     ↑ Bubble ↑

优化方式：
[Compute Stage 1]   [Send/Recv]   [Compute Stage 2]
       ↑                 ↑               ↑
    同时进行          异步通信         同时进行
```

### 7.3 mHC 的 DualPipe 优化

论文采用高优先级计算流处理关键 kernel，避免阻塞通信：

```
Normal Compute Stream:    [MLP(B)] [MLP(W)] [MLP(F)] [ATTN]...
Communication Stream:     [DISPATCH(F)]   [PP Send/Recv]...
High Priority Stream:     [F_post,res(F)] [F_post,res(B)]...
```

## 8. 实践检查清单

设计高性能算子时，按以下顺序检查：

### 8.1 分析阶段

- [ ] 列出所有操作及其 I/O
- [ ] 计算算术强度，判断瓶颈类型
- [ ] 识别可融合的操作序列
- [ ] 评估显存需求

### 8.2 优化阶段

- [ ] **Kernel Fusion**：融合有依赖的操作
- [ ] **混合精度**：存储用低精度，计算用高精度
- [ ] **重计算策略**：选择最优 $L_r$
- [ ] **通信重叠**：异步化 Pipeline 通信

### 8.3 验证阶段

- [ ] Profile 实际 I/O 和计算时间
- [ ] 验证数值精度
- [ ] 对比基线吞吐量
- [ ] 检查显存峰值

## 9. 代码模板

### 9.1 I/O 分析模板

```python
def analyze_kernel_io(operations: list):
    """分析 kernel 的 I/O 开销"""
    total_read = 0
    total_write = 0

    for op in operations:
        print(f"Operation: {op.name}")
        print(f"  Read: {op.read_elements} elements")
        print(f"  Write: {op.write_elements} elements")
        total_read += op.read_elements
        total_write += op.write_elements

    # 假设 FP32
    bytes_per_element = 4
    total_io_bytes = (total_read + total_write) * bytes_per_element

    print(f"\nTotal I/O: {total_io_bytes / 1e6:.2f} MB")
    print(f"Arithmetic Intensity: {op.flops / total_io_bytes:.2f} FLOPs/Byte")
```

### 9.2 显存估算模板

```python
def estimate_memory(
    params_count: int,
    batch_size: int,
    seq_len: int,
    hidden_dim: int,
    num_layers: int,
    expansion_rate: int = 4,
    recompute_blocks: int = 6,
):
    """估算训练显存"""

    # 参数 + 梯度 + 优化器状态
    param_memory = params_count * 2  # FP16
    grad_memory = params_count * 2   # FP16
    optimizer_memory = params_count * 8  # AdamW m, v (FP32)

    # 激活（简化估算）
    activation_per_layer = batch_size * seq_len * hidden_dim * 2  # FP16
    # 重计算策略下的激活存储
    stored_activations = (num_layers // recompute_blocks) * activation_per_layer

    # mHC 额外开销
    mhc_overhead = expansion_rate * activation_per_layer * (num_layers // recompute_blocks)

    total = param_memory + grad_memory + optimizer_memory + stored_activations + mhc_overhead

    return {
        "params": param_memory / 1e9,
        "grads": grad_memory / 1e9,
        "optimizer": optimizer_memory / 1e9,
        "activations": stored_activations / 1e9,
        "mhc_overhead": mhc_overhead / 1e9,
        "total_gb": total / 1e9,
    }
```

## 10. 总结

| 经验 | 核心要点 |
|------|----------|
| **Kernel Fusion** | 融合有依赖的操作，减少 Global Memory 访问 |
| **混合精度** | 存储/传输用低精度，计算用高精度 |
| **重计算** | 找到最优 $L_r$，平衡显存和计算 |
| **通信重叠** | 异步化 Pipeline 通信，减少 bubble |
| **I/O 分析** | 先分析再优化，用数据驱动决策 |

**一句话总结**：

高性能算子设计的核心是**最小化内存访问**——先用 I/O 分析找到瓶颈，再用 Fusion、混合精度、重计算等技术逐一击破。
