# 内存访问开销分析

## 1. 为什么关注内存访问？

### 1.1 Memory Wall 问题

现代 GPU 的**计算能力增长**远超**内存带宽增长**：

| 指标 | A100 | H100 | 增长 |
|------|------|------|------|
| FP16 算力 | 312 TFLOPS | 990 TFLOPS | 3.2× |
| HBM 带宽 | 2 TB/s | 3.35 TB/s | 1.7× |

**结论**：大多数操作是**内存受限 (Memory Bound)** 而非**计算受限 (Compute Bound)**。

### 1.2 Arithmetic Intensity（算术强度）

$$\text{AI} = \frac{\text{FLOPs}}{\text{Bytes Accessed}}$$

| AI 值 | 瓶颈 | 优化方向 |
|-------|------|----------|
| 低 (<10) | 内存带宽 | 减少 I/O、Kernel Fusion |
| 高 (>100) | 计算单元 | 使用 Tensor Core |

**mHC 的映射操作**（小矩阵乘、element-wise）属于**低 AI** 操作，因此 I/O 优化至关重要。

## 2. 论文中的 I/O 分析方法

### 2.1 分析对象

论文分析的是**每个 Token、每层的内存访问量**，不包含层函数 $\mathcal{F}$ 内部的 I/O。

### 2.2 分析维度

| 维度 | 符号 | 含义 |
|------|------|------|
| 特征维度 | $C$ | 每个 token 的隐藏维度（如 2560） |
| 扩展率 | $n$ | 残差流通道数（如 4） |
| Token 数 | - | 每次处理一个 token |

## 3. 残差连接的 I/O 分析

### 3.1 操作分解

标准残差连接的每层操作：

$$x_{l+1} = x_l + \mathcal{F}(x_l, W_l)$$

**残差合并**（不含 $\mathcal{F}$ 内部）：

```
读取:
  - x_l: C 个元素
  - F(x_l): C 个元素（假设已计算好）

写入:
  - x_{l+1}: C 个元素
```

### 3.2 I/O 统计

| 操作 | 读取 (Elements) | 写入 (Elements) |
|------|-----------------|-----------------|
| 残差合并 | $2C$ | $C$ |
| **总计** | $2C$ | $C$ |

---

## 4. HC/mHC 的 I/O 分析

### 4.1 操作分解

HC 的每层操作：

$$x_{l+1} = \mathcal{H}_l^{\text{res}} x_l + \mathcal{H}_l^{\text{post}^\top} \mathcal{F}(\mathcal{H}_l^{\text{pre}} x_l, W_l)$$

分解为以下步骤：

#### Step 1: 计算映射矩阵

$$\mathcal{H}^{\text{pre}}, \mathcal{H}^{\text{post}}, \mathcal{H}^{\text{res}} = f(\text{RMSNorm}(x_l))$$

```
读取:
  - x_l: n×C 个元素（用于 RMSNorm 和线性投影）

写入:
  - H^pre: n 个元素
  - H^post: n 个元素
  - H^res: n² 个元素
  总写入: n² + 2n 个元素
```

#### Step 2: 应用 H^pre

$$h_{\text{in}} = \mathcal{H}^{\text{pre}} x_l$$

```
读取:
  - x_l: n×C 个元素
  - H^pre: n 个元素
  总读取: nC + n 个元素

写入:
  - h_in: C 个元素
```

#### Step 3: 应用 H^post

$$h_{\text{post}} = \mathcal{H}^{\text{post}^\top} \mathcal{F}(h_{\text{in}})$$

```
读取:
  - F(h_in): C 个元素（层输出）
  - H^post: n 个元素
  总读取: C + n 个元素

写入:
  - h_post: n×C 个元素
```

#### Step 4: 应用 H^res

$$x_{\text{res}} = \mathcal{H}^{\text{res}} x_l$$

```
读取:
  - x_l: n×C 个元素
  - H^res: n² 个元素
  总读取: nC + n² 个元素

写入:
  - x_res: n×C 个元素
```

#### Step 5: 残差合并

$$x_{l+1} = x_{\text{res}} + h_{\text{post}}$$

```
读取:
  - x_res: n×C 个元素
  - h_post: n×C 个元素
  总读取: 2nC 个元素

写入:
  - x_{l+1}: n×C 个元素
```

### 4.2 I/O 统计汇总

| 操作 | 读取 (Elements) | 写入 (Elements) |
|------|-----------------|-----------------|
| 计算映射矩阵 | $nC$ | $n^2 + 2n$ |
| $\mathcal{H}^{\text{pre}}$ | $nC + n$ | $C$ |
| $\mathcal{H}^{\text{post}}$ | $C + n$ | $nC$ |
| $\mathcal{H}^{\text{res}}$ | $nC + n^2$ | $nC$ |
| 残差合并 | $2nC$ | $nC$ |
| **总计** | $(5n+1)C + n^2 + 2n$ | $(3n+1)C + n^2 + 2n$ |

## 6. 优化策略

### 6.1 Kernel Fusion

**问题**：每个操作都是独立 kernel → 多次 global memory 读写

**解决**：将多个操作融合到一个 kernel

#### 优化前（5 个 kernel）

```
Kernel 1: 计算映射矩阵
  Global Mem → Shared Mem → 计算 → Shared Mem → Global Mem

Kernel 2: H^pre
  Global Mem → Shared Mem → 计算 → Shared Mem → Global Mem

Kernel 3: H^post
  Global Mem → Shared Mem → 计算 → Shared Mem → Global Mem

Kernel 4: H^res
  Global Mem → Shared Mem → 计算 → Shared Mem → Global Mem

Kernel 5: 残差合并
  Global Mem → Shared Mem → 计算 → Shared Mem → Global Mem
```

#### 优化后（融合 H^post, H^res, 残差合并）

```
Fused Kernel: F_post,res
  读取: x_l, F(h_in), H^post, H^res  (一次读取)
  计算: x_res = H^res @ x_l
        h_post = H^post^T @ F(h_in)
        x_{l+1} = x_res + h_post
  写入: x_{l+1}  (一次写入)
```

**I/O 节省**：

| 操作 | 优化前读取 | 优化后读取 |
|------|-----------|-----------|
| $\mathcal{H}^{\text{post}}$ | $C + n$ | - |
| $\mathcal{H}^{\text{res}}$ | $nC + n^2$ | - |
| 残差合并 | $2nC$ | - |
| **融合后** | - | $(n+1)C + n^2 + n$ |

写入从 $3nC$ 减少到 $nC$。

### 6.2 混合精度

**策略**：

| 数据 | 精度 | 原因 |
|------|------|------|
| $x_l$ 存储 | BF16 | 节省带宽 |
| 映射矩阵 | FP32 | 保证精度 |
| 中间计算 | FP32 | 避免精度损失 |
| $x_{l+1}$ 存储 | BF16 | 节省带宽 |

**I/O 节省**：$x_l$ 和 $x_{l+1}$ 的传输量减半。

### 6.3 Recomputing（重计算）

**问题**：反向传播需要保存中间激活 → 显存爆炸

**解决**：前向时丢弃，反向时重新计算

```
前向:
  保存: x_l (每 L_r 层一个)
  丢弃: H^pre, H^post, H^res, 中间结果

反向:
  加载: x_l
  重计算: H^pre, H^post, H^res
  计算梯度
```

**最优重计算块大小**：

$$L_r^* = \sqrt{\frac{nL}{n+2}}$$

当 $n=4, L=60$ 时：$L_r^* \approx 6$ 层。

## 7. 实践指南

### 7.1 I/O 分析模板

```python
def analyze_io(operation_name, reads, writes):
    """
    分析单个操作的 I/O 开销

    Args:
        operation_name: 操作名称
        reads: dict, {数据名: 元素数}
        writes: dict, {数据名: 元素数}
    """
    total_read = sum(reads.values())
    total_write = sum(writes.values())

    print(f"=== {operation_name} ===")
    print(f"Reads:")
    for name, count in reads.items():
        print(f"  {name}: {count} elements")
    print(f"Total read: {total_read} elements")

    print(f"Writes:")
    for name, count in writes.items():
        print(f"  {name}: {count} elements")
    print(f"Total write: {total_write} elements")

    # 假设 FP32 (4 bytes)
    bytes_read = total_read * 4
    bytes_write = total_write * 4
    print(f"Total I/O: {(bytes_read + bytes_write) / 1e6:.2f} MB")


# 示例：分析 mHC 的 H^res 操作
C, n = 2560, 4
analyze_io(
    "H^res mapping",
    reads={"x_l": n*C, "H^res": n*n},
    writes={"x_res": n*C}
)
```

### 7.2 Kernel Fusion 决策流程

```
判断是否应该融合两个操作:

1. 是否有数据依赖？
   - 有依赖 → 可以融合（producer-consumer 关系）
   - 无依赖 → 可以并行执行

2. 融合后是否减少 I/O？
   - 中间结果不需要写回 global memory → 融合收益大
   - 中间结果需要被其他 kernel 使用 → 不适合融合

3. 融合后 kernel 是否过于复杂？
   - Register 压力是否可接受
   - Shared memory 是否足够
```

### 7.3 内存带宽利用率计算

```python
def compute_bandwidth_utilization(
    total_io_bytes: float,       # 总 I/O 字节数
    kernel_time_ms: float,       # Kernel 执行时间 (ms)
    peak_bandwidth_gbps: float,  # GPU 峰值带宽 (GB/s)
) -> float:
    """
    计算内存带宽利用率

    Returns:
        利用率 (0-1)
    """
    achieved_bandwidth = total_io_bytes / (kernel_time_ms * 1e-3)  # bytes/s
    utilization = achieved_bandwidth / (peak_bandwidth_gbps * 1e9)
    return utilization


# 示例：H100 上的 mHC kernel
io_bytes = 87088 * 4  # 每 token 的 I/O (FP32)
batch_tokens = 4096 * 1280  # batch_size * seq_len
total_io = io_bytes * batch_tokens

kernel_time = 0.5  # ms (假设)
peak_bw = 3350  # H100 HBM 带宽 GB/s

util = compute_bandwidth_utilization(total_io, kernel_time, peak_bw)
print(f"Bandwidth utilization: {util*100:.1f}%")
```

## 8. 总结

| 问题 | 答案 |
|------|------|
| **为什么分析 I/O？** | GPU 上大多数操作是内存受限的 |
| **HC 的 I/O 增长？** | 相比残差连接增长约 11 倍 |
| **如何优化？** | Kernel Fusion + 混合精度 + Recomputing |
| **融合效果？** | 读取从 $(5n+1)C$ 降到 $(n+1)C$，写入从 $3nC$ 降到 $nC$ |
| **实际开销？** | 优化后仅增加 6.7% 训练时间 |

**核心公式**：

未优化 I/O：
$$\text{Read} = (5n+1)C + n^2 + 2n, \quad \text{Write} = (3n+1)C + n^2 + 2n$$

优化后 I/O（$\mathcal{F}_{\text{post,res}}$ 融合）：
$$\text{Read} = (n+1)C + n^2 + n, \quad \text{Write} = nC$$
