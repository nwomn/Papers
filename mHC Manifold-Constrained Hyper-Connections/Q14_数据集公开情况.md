# 数据集公开情况

## 1. 核心问题

**问题**：mHC 论文是否公开了具体使用的数据集？

**答案**：**没有公开具体数据集名称**，只公开了数据量。

---

## 2. 论文中的表述

论文在实验部分（Section 5.1）提到：

> "We validate the proposed method via language model pre-training..."

但**没有明确说明**使用了哪个具体数据集。

从训练配置（Appendix A.1）可以看到：
- Training Tokens: 39.3B / 105B / 262B / 1.05T
- 但数据来源未公开

---

## 3. 推断数据来源

### 3.1 基于论文背景

mHC 论文来自 **DeepSeek-AI**，基于 **DeepSeek-V3** 架构。

DeepSeek-V3 技术报告提到使用了：
- 14.8T tokens 的预训练数据
- 内部数据 + 公开数据混合

### 3.2 可能的数据组成

| 数据类型 | 可能来源 |
|----------|----------|
| **网页数据** | Common Crawl, CC-Refinedweb |
| **代码数据** | GitHub, Stack Overflow |
| **书籍/论文** | Books3, arXiv, PubMed |
| **百科/知识** | Wikipedia, StackExchange |
| **内部数据** | DeepSeek 自有数据（未公开） |

## 5. 为什么不公开数据集？

### 5.1 行业惯例

这是**大模型领域的常见做法**：

| 公司/模型 | 数据公开程度 |
|-----------|-------------|
| **GPT-4** | 完全不公开 |
| **Claude** | 不公开 |
| **LLaMA** | 部分公开（数据源但非数据本身） |
| **DeepSeek-V3** | 公开数据量，不公开具体来源 |
| **mHC** | 同上 |

### 5.2 可能的原因

1. **商业机密**：数据配比和处理方法是核心竞争力
2. **法律风险**：公开数据来源可能涉及版权问题
3. **论文聚焦**：mHC 的贡献是方法而非数据，数据细节非必要
4. **可复现性**：方法论可复现，数据可替换

---

## 6. 对研究者的影响

### 6.1 复现挑战

| 挑战 | 解决方案 |
|------|----------|
| **无法使用相同数据** | 使用公开替代数据集 |
| **结果可能有偏差** | 关注相对性能提升而非绝对值 |
| **超参数可能需调整** | 按论文指导微调 |

### 6.2 替代数据集建议

如果你想复现 mHC：

| 规模 | 推荐数据集 |
|------|-----------|
| **小规模测试** | RedPajama-Data-1T, C4 |
| **中等规模** | The Pile (800B tokens) |
| **大规模** | SlimPajama, FineWeb |

## 8. 总结

| 问题 | 答案 |
|------|------|
| **是否公开数据集名称？** | 否 |
| **公开了什么？** | 训练 token 数量 |
| **为什么不公开？** | 行业惯例，商业/法律考量 |
| **影响复现吗？** | 影响绝对值，不影响相对比较 |
| **如何复现？** | 使用公开替代数据集 |

**一句话总结**：

mHC 论文只公开了训练数据量（最多 1.05T tokens），使用的是 DeepSeek 内部预训练数据，具体数据集名称和配比未公开——这是大模型领域的常见做法。
